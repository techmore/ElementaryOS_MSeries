Rust compositor performance

Smithay “pantheon-compositor” versus Gala/libmutter on the M1 Pro · evidence through 19 October 2026

Experimental — no performance win is established.

The Rust compositor is an opt-in session beside Gala, not a replacement. The retained samples were taken under different workloads and session ages, none is a matched A/B, and whole-system power has not been measured. Gala remains the session that logs in. Nothing on this page should be read as a Rust advantage; it records what has actually been measured, how, and what is still open.

What is being compared

Gala / libmutter

The established Pantheon compositor: Wayland session, shell integration, input stack and app compatibility. The baseline every Rust number has to beat.

Baseline

Rust / Smithay

A focused Rust compositor implementing the Pantheon behaviors this stack needs — panel/dock shell protocol, window basics, tiling, XWayland, IBus input — not a port of Mutter. It reached native scanout on the internal panel in isolated logins, with Wingpanel starting and the owner's dock opt-out honored.

What would count as “better”

  • The same machine, display mode and scale, workload, session age, and panel/dock composition in both sessions.
  • Matched idle and interactive captures of the whole process trees, not one process picked from each.
  • Login-to-first-usable time from the journal, with visual confirmation — not a journal milestone alone.
  • Frame pacing and input-to-visible latency, which have not been measured at all yet.
  • Power from a battery-discharge run or an external meter; mains battery flow of 0 mW says nothing.
  • A crash-free soak and working recovery before any daily-use claim.

How the numbers are produced

# matched 30 s captures in each session (same workload label and display mode)
bash mseries/pantheon-rust-compositor/collect-session-metrics.sh gala 30 idle internal-panel
bash mseries/pantheon-rust-compositor/collect-session-metrics.sh rust 30 idle internal-panel

# reduce a capture to per-process mean/median/min/max
python3 mseries/pantheon-rust-compositor/summarize-metrics.py metrics/*.csv

# startup milestones and per-thread profiles
bash mseries/pantheon-rust-compositor/collect-session-startup.sh rust
bash mseries/pantheon-rust-compositor/collect-session-thread-profile.sh

Raw captures are retained in mseries/pantheon-rust-compositor/metrics/. The collectors change nothing on the running session; they only read /proc and power-supply state.

Trying it, and going back

bash mseries/install-pantheon-rust-compositor.sh --dry-run      # checks only
sudo bash mseries/install-pantheon-rust-compositor.sh --install --yes --deb <package>
sudo bash mseries/install-pantheon-rust-compositor.sh --select --yes       # next login
sudo bash mseries/install-pantheon-rust-compositor.sh --restore-gala --yes # rollback

The package installs beside Gala; the Gala session entry, package and binary are never modified. Selecting the Rust session only changes the LightDM autologin drop-in, takes effect at the next login, and never logs anyone out.
