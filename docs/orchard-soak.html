CPU and memory

Across 87.00 minutes of settled inactive idle intervals, app CPU averaged 0.17% of one core; reaped CLI clients averaged 0.05% separately. The largest observed five-second workload interval was about 30% of one core during a deliberate frame probe. These figures exclude the Incus daemon, VMs and compositor.

Settled RSS medians increased from 186.25 to 190.14 MiB (3.89 MiB); private medians increased from 69.22 to 74.77 MiB (5.55 MiB). This small growth is real in the samples; its cause is unconfirmed. Each cycle returned output buffers to zero. Tracked Python object counts at cleanup were 30,682 → 29,881, while rows/cards/histories stayed at two and read/timer slots at two. These observations do not prove absence of all leaks.

Workflows and separate observations

All seven cycles passed container creation and duplicate-name protection, Run and bounded Unicode output, files and transfers, resource settings, shared folder and TCP forwarding, lifecycle and snapshot restore, clone/rename/delete, native VM creation and commands, Terminal login, backup export, and creation cancellation. Inventory/output cleanup succeeded after every cycle. The separate standard window was observed for only 26 minutes: settled RSS 146.73 → 146.61 MiB, private memory 44.06 → 44.11 MiB, descriptors 35 → 35. It is not a full-duration control. The initial 4.2-minute attempt and subsequent 4.5-second cancelled retry are excluded from the main analysis. The latter hit an Incus update-lock cleanup race; its single remaining fixture was removed during the stop request, with zero owned fixtures remaining.

Fixes and verification boundary

  • Record missing/partial frame feedback explicitly; preserve raw feedback and action timestamps before marking a probe unsuccessful. Long stalls remain in the distribution.
  • Require sufficient action coverage, completed cycle count and minimum duration for a qualification pass.
  • Retain per-cycle frame files, timestamps and scheduled intervals from the existing soak extension.
  • Bounded cleanup retries for Incus’s transient update lock, rechecking exact owned names and creation tokens each time; cleanup errors retain a failed qualification and ending timestamp.
  • Removed the proposed focus-raising option. Finishing this report launches no applications or tests.
