Orchard for Incus: native UX and performance audit

October 18, 2026 · elementary OS M-series · Python/GTK4 application

What changed

  • Search lives in the instance sidebar and matches name, image, status and IPv4. Empty results are explicit, Escape clears search, and keyboard navigation keeps the selected detail aligned with visible results.
  • Dashboard cards are native keyboard-accessible buttons. Ctrl+1/Ctrl+2 switch views; Ctrl+? and the application menu expose shortcuts; Menu/Shift+F10 opens instance actions.
  • The header fits 780 px; the Devices form scrolls and keeps forwarding/sharing controls reachable. Light/dark fixture screenshots were inspected at 1180×740 and 780×480.
  • Refreshes coalesce while busy. Tab/resource/image-catalog reads keep one active and one replaceable pending request per destination; superseded results and errors are discarded. JSON reads default to 20-second timeouts.
  • Old snapshot/device/file actions disappear during a new read. Settings cannot apply values from a previously selected instance. Busy operations cannot start twice.
  • Window timers, CSS subscriptions and the monitor are cleaned up on close. Event bursts share two delayed address checks. Launching the monitor process no longer falsely proves the event stream is connected.
  • Command output uses chunked UTF-8 decoding and a bounded 65,536-character mailbox with batched UI deliveries. Each text buffer retains 262,144 characters; skipped fast output is labelled. Scrolling back pauses automatic tail following.
  • Dashboard cards populate in batches of 16. Hidden dashboard work and offscreen chart updates are deferred; scrolling refreshes newly visible charts. Unchanged charts/sidebar rows skip redundant updates. History cleanup scans the inventory once.

Limits and remaining work

  • Single sequential before/after run on the owner desktop; timings vary with other workloads.
  • UI-thread show() timing, not end-to-end frame latency; initial_ms excludes deferred dashboard construction.
  • No live container mutation, real Wayland frame pacing, long-duration RSS or full dialog/action qualification.
  • Sidebar and dashboard still use retained GTK rows; very large inventories need virtualization.
  • The Vala manager is build-tested only; its UI/performance problems are not repaired in this pass.
  • Two manager desktop entries may still coexist. The Python app is the installed foreground target for this pass; no Vala launcher or panel module was removed.
  • Creation cancellation/cleanup still uses the existing implementation; daemon operations, terminal/file-manager integration and privileged controls need a separate live workflow qualification.
