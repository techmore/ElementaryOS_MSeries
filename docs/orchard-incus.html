Orchard: verified on the real Wayland desktop

October 18, 2026 · Installed Python/GTK4 manager · 11 live workflow groups passed · 103 unit/integration tests: 97 passed, six opt-in live tests skipped.

Fixes from desktop verification

  • Creation cleanup preserves existing guests. New jobs set a unique marker atomically in the launch configuration. Failed/cancelled cleanup verifies that marker before cancellation or deletion, waits for client exit, bounds CLI requests, and treats malformed ownership data conservatively. Duplicate names are rejected in the form and launch path. A deliberate stale-inventory collision was rejected by Incus and the original disposable guest stayed intact.
  • Settings apply once. CPU, memory and autostart now use one idempotent bulk update. Clearing an already-absent key succeeds; double activation is suppressed, and completion cannot reload another instance's edits.
  • Device edits serialize. Per-instance metadata queues prevent Orchard's own concurrent removals from producing ETag conflicts. Duplicate clicks are ignored; external conflicts remain errors rather than being overwritten.
  • Selection survives rename and filters. A refreshed renamed row is selected explicitly, and opening a dashboard target clears a filter that hides it. Full long instance names have a detail tooltip.
  • VM setup is actionable. Creation offers explicit Secure Boot selection, with secure defaults. The tested Alpine VM used the opt-out required by its image. Run explains guest-agent startup; More offers an agent-independent Console launcher.
  • Native layouts fit. The creation form scrolls inside the dialog. Devices now has a single page scrollbar, keeping inventory rows visible above the editing form. The native narrow window measured 780×510 including the titlebar.

Reproduce

From mseries/orchard-incus, with a live Wayland session, Incus access, cached Alpine container/VM images and AT-SPI available:

audit_dir=$(mktemp -d)
GDK_BACKEND=wayland python3 tools/qualify-wayland.py \
  --source "$PWD" --output "$audit_dir" --run

The audit creates and deletes uniquely named guests. Its driver guards exact fixture names/images/limits and host output destinations; creation markers protect cleanup. Use a fresh output directory. The receipt records source hashes; the frame JSON and screenshot remain local artifacts. tools/wayland-frame-control.py provides the simple GTK comparison.

Scope and driver corrections

  • Native GTK actions were invoked programmatically. Files listing and real CLI transfer round trips passed; Terminal reached a one-shot guest login profile; the elementary backup Save portal was driven through AT-SPI and the archive was independently listed with tar.
  • Interactive upload/download picker selection, physical keyboard/focus traversal, interactive Console input, long-duration RSS/thermal soak, very large real fleets, other themes/scales and the separate Vala manager/panel remain outside this receipt.
  • Initial driver errors included responding before a dialog was mapped (GTK Wayland critical/crash), deprecated AT-SPI method dispatch, an overly short VM-agent wait and foreground entry text changes. The final driver waits for mapped/painted dialogs, guards fixture names and allows VM startup. Preliminary action-latency values used different attribution and are not a before/after speedup claim.
  • One altered-name fixture from an interrupted early driver was separately identified and removed. The final sweep found no audit fixtures; original owner guests remained present and running.
