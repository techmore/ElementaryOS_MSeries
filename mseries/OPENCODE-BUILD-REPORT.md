## Findings: concrete blockers / mistakes

1. Local tool blocker (expected but confirmed): `just` and `podman` are absent on
   this workstation. Full `just mkosi summary` and `just do-daily` must run in
   CI (`ubuntu-26.04-arm`) or a prepared build environment. No ISO qualification
   can be claimed from this preflight.

2. Concrete overlay defect: `mkosi.images/apple-silicon/mkosi.finalize` is a
   pruning overlay, but its allowlist does not preserve:
   - `etc/xdg/autostart/mseries-brightness.desktop`
   - `usr/libexec/mseries-brightness`

   As written, both brightness-control files are deleted from the Apple Silicon
   layer before ExtraTrees consumption, even though the overlay packages
   `python3-gi` for that script. The allowlist needs matching `! -path`
   entries if brightness keys are intended to ship.

3. Workflow depends on full release machinery despite its experimental scope:
   `just do-daily` invokes `_do-release`, including `assemble-iso.sh`, which
   relies on host `rsync`, `systemd-analyze`, podman images, and
   `./mkosi.version`. The latter is not present in the repository; it is either
   generated during the mkosi build or needs explicit creation before assembly.
   This should be confirmed in the first CI build log. If generated by mkosi,
   no action is needed. If not, assembly will fail at `just _get_timestamp`.

4. Arm64 config cleanup note: `arch.arm64.conf` still pulls `driver-nvidia` and
   `driver-nvidia-addon` on arm64, matching upstream. This is not necessarily
   wrong, but the first build log should be checked for arm64 NVIDIA package
   resolution errors.

5. Low-priority naming cleanup: the overlay still uses
   `omarchy-wifi-resume-fix.service` alongside M-series scripts. It is wired
   correctly, but should be renamed consistently in a later cleanup.

6. The ignored generated file `__pycache__/mseries-brightnesscpython-314.pyc`
   was created during this preflight and removed afterward; it is not a source
   change.
