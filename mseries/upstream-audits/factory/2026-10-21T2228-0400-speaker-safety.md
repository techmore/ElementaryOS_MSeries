## Ranked findings

1. **Speaker protection was absent from fresh ARM64 images.** The transformed
   M1 Pro runs `speakersafetyd`, while the Apple Silicon overlay, live ISO and
   sysupdate consumers did not install or enable it. Added the safety daemon
   only. The optional DSP chain remains out because fresh-image first-boot
   volume behavior has not been qualified.
2. **Apple boot remains the main acceptance blocker.** The generic 7.0 ARM64
   kernel, Apple DTB/m1n1 handoff, UKI/ESP selection, encrypted-root path and
   recovery remain unqualified on physical Apple hardware. The M4 PR's isolated
   research builds do not change that status for the M1 Pro factory image.
3. **Hardware firmware and runtime parity remain partial.** The source overlay
   carries Wi-Fi firmware provisioning, resume recovery and HID initramfs
   selection; dock Realtek firmware is still documented as not wired. Bluetooth
   recovery remains opt-in. Panel plugins and app customizations are source
   payloads with build-time version checks, not evidence that they loaded in an
   Apple session.

## Change and source provenance

`speakersafetyd` is declared in the ARM64 Apple Silicon overlay and both
consumers (liveiso and sysupdate). A `multi-user.target` wants link is retained
through overlay pruning and shipped in `/usr`, including the sysupdate artifact.
The service is the safety-only component; `asahi-audio`,
`alsa-ucm-conf-asahi`, and the PipeWire LV2 filter chain are not enabled by this
change.

- Ubuntu package: [`speakersafetyd` in Resolute](https://packages.ubuntu.com/resolute/speakersafetyd),
  binary version `1.1.2-4`, source package `rust-speakersafetyd 1.1.2-4`,
  `universe`, ARM64 build available. Package source identity is the Ubuntu
  source version; the package index does not expose a Git commit.
- Ubuntu source listing: [Resolute ARM64 package details](https://packages.ubuntu.com/resolute/arm64/sound/speakersafetyd).
  Image package retrieval remains through the configured signed Ubuntu archive;
  no `.deb` digest was captured in this source review.
- Upstream: [AsahiLinux/speakersafetyd](https://github.com/AsahiLinux/speakersafetyd),
  tag `1.1.2`, commit `0e525dd3386f4a33c142f6b297e376ef8152792e`; upstream
  license is MIT. The source is not copied into this repository. The Debian
  systemd unit at source package `rust-speakersafetyd/1.1.2-4` declares
  `WantedBy=multi-user.target`.
- Model applicability: ARM64 Apple Silicon; the transformed M1 Pro has
  previously run the same package. This is not a physical qualification of the
  factory image or any other Apple model.

## Artifact-only build attempt

The artifact-only `daily-9.0.yml` workflow was dispatched at commit
`b908507cbccbac75911d350bbe74a0270b7d7e6e` with Fairydust disabled. It fetched
and configured `speakersafetyd arm64 1.1.2-4` from the configured
`ports.ubuntu.com` Resolute universe archive. The retained `image-content.log`
reports “Built live ISO hardware payload check passed”; this confirms the
package-owned service link resolves in the generated liveiso tree. It does not
represent a completed installer ISO.

The same workflow failed while `systemd-repart` assembled the sysupdate output:
`Verity signature partition is empty`. Mkosi then reported that no split OS
partition artifacts were available to compress. The later installer checksum
step failed because `elementaryos-*.iso` did not exist, so no ISO was uploaded.
The retained build-record artifact is
[`os9-mseries-build-record-39712066587`](https://github.com/techmore/ElementaryOS_MSeries/actions/runs/39712066587).
The recipe's final chmod allowed the `just do-daily` build command to return
success despite mkosi's failure; the checksum step exposed the missing ISO
later. This fail-open reporting should be corrected with the repart failure in
a follow-up build-fix change, not folded into the speaker package change.
