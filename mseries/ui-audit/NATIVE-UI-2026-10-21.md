# Native UI audit continuation — 2026-10-21

Issue #242 remains open. The [38-family inventory](surface-inventory-2026-10-21.json)
expands all named issue surfaces and includes additional shipped apps. Its baseline
is `fe390c78ea47808290469173d9a0dd68263b3f35`; prior receipts keep their original

## Findings resolved in source

| Finding | User impact | Resolution |
|---|---|---|
| Troubleshooter calls verification helpers synchronously at startup and in actions, with 10/120-second timeouts | A window can appear late or freeze while checks run | Move commands and status decoding to a bounded worker, serialize verification actions, show pending/error/retry, retain previous results, reject stale completion and cancel/reap the owned helper on close |
| AirPlay discovery, receiver changes and group selection invoke blocking subprocesses on the GTK thread | Controls stop responding during backend discovery/failure | Worker-based loading/actions, disabled duplicate operations, clear recovery, native labelled checkboxes, retained last-known state, explicit Refresh, bounded output selection and ignored completion after close |
| Display arrangement paints fixed-size raw Cairo labels inside clipped monitor rectangles | Names/modes are visibly cut off; text ignores system font scaling and monitor selection is pointer-only | Bounded Pango layouts with ellipsis and GTK font, full tooltip/accessibility summaries and keyboard selection without applying any monitor configuration |

## Checks

`bash mseries/ui-audit/run-private-checks.sh OUTPUT` passed all combinations of
light/dark and actual GTK scale factors 1/2 for the changed Troubleshooter and
AirPlay and Displays. Each combination runs four GTK4 tests, one multi-stage
AirPlay GTK3 test and six fake-display canvas tests. The runner records screenshot
pixel dimensions and source content identity; see the retained
[receipt](receipts/native-ui-2026-10-21.json). It uses private files, Xvfb and D-Bus
with activation disabled. No live model, verify helper, service, PipeWire or
monitor operation is invoked by the fixtures.

Troubleshooter checks delayed startup/status, confirmation/run heartbeat, duplicate
suppression, malformed/nonzero result, retry, retained content, cancellation,
helper reaping, stale completion and timeout recovery. AirPlay checks delayed
loading/toggle heartbeat, label presence, backend error, retry, retained selection
empty results, wrapped long names at 360px and close while pending. Displays checks bounded long labels, widget font changes,
full accessible/tooltip text, named controls and real private-window X11 Right/Tab events without display writes.

The 12 captured PNGs cover ready/error Troubleshooter and ready AirPlay in both
themes/scales. Representative ready/error captures were inspected: visible
controls, readable status and no clipping at 680×560 / 360×274 logical pixels;
scale2 device pixels are doubled. The original immediate capture could precede
GTK repaint; the final capture drains the main context before taking the image.
The host's elementary GTK3/4 stylesheets were available and hashed. Ubuntu CI
without those stylesheets records its GTK fallback explicitly and cannot establish
elementary-theme appearance.

Additional unchanged-backend checks: 73 local-AI unit tests and six AirPlay core
tests passed; Python compilation, runner shellcheck and whitespace checks passed.
Hosted CI records current source checks and uploads fixture logs/images.
