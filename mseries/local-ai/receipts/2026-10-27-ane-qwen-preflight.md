# Qwen ANE decoder preflight — 2026-10-27

This records a read-only investigation and host-only tests, not an ANE model
benchmark. The requested TensorFold-specific ANE implementation is not available
in these repositories and no ANE/MLX performance comparison was run.

## What the Qwen implementation needs

The upstream [staged decoder documentation](https://github.com/joshuaswarren/omarchy-ane/blob/0916411a8a9419ca589d14b53d89c425e8083685/tools/staged-qwen/README.md)
describes a Linux runner that consumes a manifest and 38 compiled per-program
ANE artifacts for Qwen3.8-2B, generated by the macOS/ANEForge exporter. The
upstream [export receipt](https://github.com/joshuaswarren/ane-linux-experiments/blob/b1f2cbe338ef33f9befb320b98ef83096b37980b/receipts/2026-09-25-qwen-ane-decoder-fix/README.md)
describes an ANEForge split-decode branch distributed as a local git bundle,
model GGUF, macOS compile/export and conversion to Linux `.anec`, with a
load-bearing layout guard. No corresponding `prog_000.anec`, compiled staged
bundle, Qwen GGUF, or ANEForge split worktree was found in the scoped local
cache, ANE installation, `/tmp`, or `/var/tmp` searches. The public repository
includes runner code and receipts; this is not evidence that the necessary
compiled model assets are publicly downloadable. We did not produce or run a
substitute artifact. The local GPU checkpoint is Qwen3.5-2B MLX 4-bit; it is
not established as the same checkpoint or quantization as upstream's Qwen3.8
GGUF. A fair comparison requires matching weights, tokenizer, prompt, length,
measurement boundaries and correctness verification.

Upstream's [M1 staged-Qwen layout gate](https://github.com/joshuaswarren/ane-linux-experiments/blob/b1f2cbe338ef33f9befb320b98ef83096b37980b/receipts/2026-09-25-jwm1-qwen-ane-layout-gate/README.md)
reports 38 ANE submissions/token, 8.23 tokens/s and peak RSS 8.38 GB on a
T8103 under its own benchmark. This is external evidence, not an M1 Pro result
and not directly comparable to our MLX Qwen timings. That memory peak plus the
6 GiB desktop reserve exceeds the roughly 10.26 GiB available during this
preflight; the model was not admitted. The host may have different memory needs,
but an estimate below the upstream peak would need independent evidence.

## Host-only checks

Using the existing isolated MLX Python environment, from a fresh `/tmp` clone:

```
python -m unittest tools.test_hwxv2_to_anec tools.test_production_anec_probe \
  tools.test_ane_contract tools.test_aneforge_qwen_reference \
  tools.test_compare_qwen_reference
# 82 tests; 5 failed, all in tools.test_hwxv2_to_anec
python -m unittest tools.test_ane_contract tools.test_aneforge_qwen_reference \
  tools.test_compare_qwen_reference
# 18 tests passed
```

At this revision the converter sets `TILE_UNIT = 0x200` and documents 512-byte
header tile counts, while the five failing tests expect the older 0x4000-byte
count convention. This describes an observed source/test discrepancy, not a
proven converter bug or a validated driver ABI. Determine the correct units
against the actual libane and kernel ABI and qualified fixtures before any
converted artifacts are submitted to the ANE. Upstream itself warns that
bring-up and incorrect register programming can hard-reset a machine.
