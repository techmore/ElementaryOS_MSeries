# M1 Pro local AI qualification on October 16 2026

Qwen3.5 9B through private Linux MLX is the provisional general-assistant choice on this M1 Pro 32 GB. It passed 12 of 15 short task trials and all 9 MCP workflow trials. Liquid 1.2B generated short answers much faster but made more task and tool mistakes. Newelle is configured for local desktop chat and personal summary memory. Crush's larger prompt requires a separate 16K profile. Long coding and Bonsai trials remain subject to the quiet-window qualification below.

Five fixed synthetic cases, each repeated three times at temperature zero and a 512-token output limit: customer JSON extraction, clock arithmetic, a log with a planted instruction, order-preserving deduplication, and merging intervals without mutating input. Repeats check stability; this small deterministic suite is not a broad intelligence or coding benchmark. The grader accepts fenced JSON/code, but arithmetic requires exactly HH:MM. Code runs only after a restrictive AST gate in an isolated interpreter with CPU, memory, file-size and time limits.

Qwen9 passed extraction, log calibration and both code functions every time; it answered the clock problem incorrectly as 10:45. Qwen4 calculated 11:40 in an explanation but failed the requested format, followed the planted Wi-Fi claim, and mutated the interval input. The 7B coder passed extraction and deduplication but failed the other cases. Liquid passed extraction and both code cases but failed arithmetic and the log calibration. These observed failures are why the assistant uses a deterministic `add_minutes` tool and keeps model-generated diagnoses advisory.

The decode estimate is `(completion_tokens - 1) / (last-read-time - first-text-time)`, using streamed API timing. It includes server/runtime behavior; it is not a standardized kernel throughput measurement. First requests are labeled separately. llama.cpp reused substantial prompt prefixes on repetitions; MLX and llama have different caching. Use recorded cache counts before interpreting time-to-first-text differences. Models ran sequentially with the existing desktop apps retained, on kernel `7.1.13-3-2-ARCH`, schedutil, and the recorded CPU caps. No old/new MLX speedup or macOS comparison is established.

## Long requests and resource policy

The six-GiB desktop reserve is enforced at admission and continuously. A hard limit of 3500 fan RPM or 80 C stops inference after three samples. RPM is a proxy for noise; no acoustic meter or dBA result is available. Long prompt tests exposed thermal overlap with an independent Rust/HTTP load test. Those processes were preserved at the owner's request. Interrupted runs stay in `exploratory/`; they are not scored as completed model failures.

The final supervisor adds cooling pauses for its own process group before the hard limit, with baseline-relative fan hysteresis and 70/65 C temperature hysteresis. A changed idle baseline cannot leave requests stalled indefinitely: below the hard limits, six-second compute bursts follow thirty-second cooling intervals when needed. Paused processes are resumed before orderly shutdown, and shutdown cannot pause cleanup again. KillMode=mixed lets MLX clean up reservations before systemd kills descendants. One stale reservation from the earlier shutdown ordering was removed only after confirming its owner had exited. Missing sensor data fails closed.

Crush rejected the initial 8K context because its prompt was over 11K. The corrected coding profile uses Qwen9 at 16K, one retained cache, and thinking disabled by default. The pinned upstream admission estimate is 7.93 GiB, including workspace/cache allowance; the profile budgets 8 GiB plus six GiB for the desktop. Coding file-edit qualification is recorded separately as it completes. Hermes enforces a 64K minimum; its attempted tool run retained an old tool cache and was interrupted during the busy thermal interval. A clean-tool, cache-enabled 64K profile is experimental and requires an 11 GiB model budget plus the desktop reserve. Newelle's verified summary memory is the default personal path.

Bonsai 2 9B official Q2_0 weights are pinned and checksum-verified. The private Vulkan path loaded them; the first completed short responses decoded around 5.6 tokens/s. The run was stopped during an interval-generation answer by the fan policy while the other load test was active. This is an incomplete candidate evaluation, not a completed 15-case ranking. PQ2_0/PTQ1_0 and the 27B dev file requiring Prism's fork are not substituted into upstream llama.cpp. The larger 30B coder is not installed or benchmarked: its 21 GiB admission estimate plus reserve does not fit the busy desktop, and the current private ICD reports a roughly 15.5 GiB recommended working set.

## Runtime packaging and developer tracking

Private MLX v0.7.33 passes float32 matrix multiplication, integer shifts/XOR and twice-compiled rsqrt/RMSNorm checks against NumPy. The compute-only Honeykrisp ICD remains isolated from desktop Mesa. The offline factory installer verified 36 vendored wheels against the hash lock and staged the runtime in a temporary root. Four image wiring/pruning tests and the effective mkosi summary pass. This does not establish a full build or hardware boot with the new AI payload. The running kernel, bootloader and audio stack were preserved.

The branch watcher captures 1,103 public heads across the eight selected repositories at the recorded snapshot, plus open PRs and immutable ahead/behind comparisons. Full head lists are retained as workflow artifacts; hashes/counts fit the persistent dashboard. All-head digests catch new unnamed developer experiments; selected branches and the ten most active PRs per repository receive detailed comparisons. Ahead-by counts do not establish patch novelty or hardware applicability. Fetch failures and pagination limits are visible and never interpreted as an unchanged or clean state. The existing six-hour workflow activates these changes once they land on main.
