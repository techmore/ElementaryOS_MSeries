# Native app audit and SDK templates (2026-10-23)

What we ship or maintain today, what kind of app each is, how much of it the SDK can express now, what blocks the rest,
and the order to port. Sizes are lines of source counted on `origin/dev`. **Archetypes and "SDK today" are my reading of the
names, sizes and what I know of each app; I did not read every app's code.** Treat each row as a hypothesis to correct.
Related: [SDK-AUDIT-2026-10-23.md](SDK-AUDIT-2026-10-23.md), [MINIMAL-SYSTEM.md](MINIMAL-SYSTEM.md).

## 1. Archetypes and templates

Ten recurring shapes cover the apps. Six now have a working template (`msdk templates`, `msdk new <template> <dir>`); each one
passes `msdk check` and its own gates in the test suite, and renders with `msdk-run`.

| Archetype | Template | What it demonstrates | Status |
|---|---|---|---|
| Settings page | `settings` | Switch, dropdown, defaults (`initial`), saved values (`persist`), reset | Built |
| List and detail | `list-detail` (Quick Notes) | Search, add, delete with confirm, edit, selection, saved list | Built |
| Dashboard | `dashboard` | Cards of readings refreshed from commands, replace-by-id, error path | Built |
| Task runner | `task-runner` | Busy state, output, success toast, recoverable failure | Built |
| Wizard | `wizard` | Steps, back/next, validation gating, summary | Built |
| Launcher panel | `launcher-panel` | Panel surface of icon buttons that launch apps | Built (anchoring pending) |
| Shell panel with live windows | dock (`mseries-dock`) | Window feed, pins, indicators, focus/cycle/launch | Built as Rust logic, see PR 548 |
| Kiosk login | greeter (`mseries-greeter`) | Fullscreen card, secret entry, multi-step auth | Built as Rust logic |
| Chat / transcript | none | Streaming transcript, composer, permission cards | Blocked: components and services missing |
| Analyzer / viewer | none | Folder chooser, background scan, chart | Blocked: chart, chooser, scan service |

## 3. What the SDK still cannot do (gaps, by how many apps need them)

1. **Panel indicator / popover host.** Wingpanel indicators and Switchboard plugs are plugins loaded into other processes. An SDK
   app is its own process, so it cannot appear in today's panel. The SDK `panel` and `popover` surfaces need the Rust panel
   (the Wingpanel replacement in the shell plan) or the Pantheon shell protocol client. Blocks about 10 apps.
2. **Services missing for declared capabilities:** notifications, timers (`every N seconds`), GSettings, keyring, folder chooser,
   HTTP/WebSocket, streaming subprocess output. The capability names exist; the calls do not.
3. **Components missing:** Transcript/Markdown/code block, Chart (sunburst, sparkline, bar), Tabs/Stack, Table, Calendar grid,
   Log/Terminal view, Image/Avatar, Menu, Toolbar groups. Recorded in `sdk-bench/GAPS.md` when first needed.
4. **Rules cannot parse or compute beyond `add`:** no JSON/text parse into list records, no arithmetic expressions, no
   conditionals except `when`. Those cases use `"logic": "rust"`.
5. **Panel anchoring:** `panel` surfaces open as plain windows until the Pantheon shell protocol client binds
   `get_panel`/`set_anchor`/`set_size`/`set_hide_mode`.

## 4. Port order

1. Done: greeter, dock (logic and rendering; anchoring pending).
2. `mseries-updates` (task runner, already Rust, backend change coming with Arch).
3. Settings family: work-mode, touchid-settings, display-space, ui-scale, as standalone windows first.
4. Python task runners: polybagger print manager, phone-setup (wizard).
5. Dashboards and indicators once the panel host exists: codexbar, repobar, share-eyes, quick-settings.
6. List/detail: calendar (needs the grid), Torrential, notes.
7. Large: Orchard, then `claude-pantheon-rs` and Disk Space (they need the missing components, so they drive the next vocabulary).

The templates double as the first benchmark: a Qwen ~4B run that creates the first four archetypes from the spec text, using only
`msdk describe/complete/explain/gate`, is the early signal that the language is usable.
