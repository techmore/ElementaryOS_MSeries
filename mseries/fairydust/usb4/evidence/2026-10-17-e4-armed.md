## How the DTB was built

- AsahiLinux/linux `ce9f2eba` (the PKGBUILD `_commit`), sparse checkout of
  `arch/arm64/boot/dts/apple`, `include/dt-bindings`, `scripts/dtc`.
- DT hunks of patches 0001, 0002, 0006, 0009, 0010, 0015 applied; compiled with
  the in-tree dtc (1.7.2, built on macOS) after kbuild-style `cpp`.
- **Pipeline check:** the same tree without 0015 is **byte-identical** to the
  j314s DTB in `boot.bin.pre-sep-20261017-100328`.
- **Touch ID kept:** `boot.bin` had been edited earlier today
  (`mseries/aurora-touchid-state.md`: SEP `status = "okay"`, the `sep` alias,
  `spi2-pins`, `spi@39b108000` + `fingerprint@0`). A plain swap would have
  dropped them, so [`../e4-touchid-delta.dtsi`](../e4-touchid-delta.dtsi)
  re-applies them by node path. Without 0015 + delta, the result is the
  installed tree (identical apart from phandle numbering).
- E4 tree, `fdtget`: `dcpext0` `mux-controls` → `mux@b0304c000` cell 1,
  `mux-index` 0, `apple,dptx-phy` 1, `apple,dp-tunnel-phy` → `phy@e50000`,
  `ports` only `port@0`; `dcpext1` → crossbar cell 0, no tunnel properties;
  NHI `apple,dp-source` → `dcp@289c00000`. Matches the 0015 commit message.

## Side effects (all Linux entries share boot.bin)

- Built-in HDMI has no display controller while E4 is installed.
- `dcpext1` is back to stock DP-altmode wiring on every entry.

## After the boot, check

```
sudo dmesg | grep -E '289c00000.dcp|dispext0|dpin0|DPINDBG|DPRX|0:5|1:14'
```

Expect `289c00000.dcp` to probe (m1n1 enables it), `Switched dpin0 to
dispext0,0`, and `… dptx target phy: 1 … tunnel: 1`. Success is the firmware
sending `set_active_lane_count` / link-rate calls, then EDID.

## Rollback (macOS or Linux, ESP)

```
cp "/Volumes/EFI - ASAHI/m1n1/boot.bin.pre-e4-20261017-120704" "/Volumes/EFI - ASAHI/m1n1/boot.bin"
```
(`/boot/m1n1/…` from Linux). `next_entry` clears itself after one boot.
