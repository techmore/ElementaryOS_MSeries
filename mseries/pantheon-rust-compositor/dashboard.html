Could Gala run on the Rust stack?

Gala is itself a Wayland compositor built around libmutter, Clutter and Mutter’s Meta APIs. The local Gala 8.6.2 audit found 79 Vala files using Meta.* across 24,534 lines of core source. Reusing Gala as a shell inside Smithay would require separating and porting much of that compositor-specific code.

That is a much larger rewrite than implementing the Pantheon behaviors we need, and it would not change the DCP/kernel HDMI limit. Keep Gala as the daily baseline; port a behavior only when it appears in the M-series acceptance list, then require matched performance, visual quality and reliability wins before considering a swap.

What would count as “better”

The Rust branch should only be called a performance improvement after the same M-series machine, display mode, workload, session age, and panel/dock composition are compared against Gala. Track login-to-first-usable time, CPU, total session RSS, GPU activity, latency, battery discharge or measured input power, and crashes/recovery.

The owner noticed this ~2.1 s wallpaper-to-panel gap as slow, despite reporting good overall opening time. Journal milestones are not direct measures of visual perception or first interaction.
  • collect-session-thread-profile.sh: captures per-thread CPU and resident memory with pidstat. An exploratory Gala profile is recorded below; a Rust thread profile still needs a future Rust login.
